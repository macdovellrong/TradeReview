# 可编辑的全局绘图设计

日期：2026-04-17  
项目：TradeReview  
范围：增加类似 TradingView 的图形选择与直接编辑能力，新增矩形绘图工具，并基于时间与价格坐标实现跨应用重启的全局绘图持久化。

## 1. 背景

当前 `ui/main_window.py` 中的绘图实现，已经支持创建和渲染以下图形：

- `hline`
- `vline`
- `line`
- `fib`
- `fib_ext`

最近的一次重构已经把 Fibonacci 数学逻辑、绘图 spec 归一化和多点绘图会话移动到了 `ui/drawings/`，但运行时能力仍然有三个明显限制：

- 现有图形创建后不能直接编辑
- 还没有矩形绘图工具
- 图形只存在于内存中，重启后就会丢失

用户希望交互模型更接近 TradingView 这类软件：

- 点击图形即可选中
- 选中后显示可见的控制点
- 拖拽控制点可编辑图形
- 拖拽图形主体可整体移动
- 所有周期图表都显示同一批图形
- 图形全局持久化，不依赖当前加载的数据文件

用户明确表示不希望图形绑定到某个数据库文件。图形应当使用 `时间 + 价格` 坐标作为锚点，并在下次启动时全局恢复。

## 2. 目标

- 为已支持的绘图类型增加直接选择与编辑能力。
- 新增 `Rect` 工具按钮，用于矩形创建与编辑。
- 保持现有跨图表的全局同步行为，使同一图形出现在所有启用的图表中。
- 使用 `QSettings` 对所有图形进行全局持久化。
- 使图形坐标独立于当前加载的市场数据文件。
- 使用一种将图表渲染职责与绘图交互职责分离的架构。
- 引入每种工具对应的专用可编辑图元类，便于后续新增更多图形类型。

## 3. 非目标

- 本轮不做属性面板，不支持通过数值输入手工编辑。
- 本轮不做吸附到 K 线、高低点或其他参考线。
- 本轮不做旋转手柄、复制粘贴、锁定、隐藏或图层顺序控制。
- 本轮不做绘图文件夹、模板，或按品种/按文件区分的绘图库。
- 第一版不追求完全复刻 TradingView 的所有交互细节。

## 4. 已确认的产品决策

- 采用 `3 + 2` 架构：
  - 一套独立于图表核心的绘图子系统
  - 每种工具对应专用的可编辑图元类
- 图形是全局的，不与当前加载的 DuckDB 或 parquet 文件绑定。
- 图形锚点按时间与价格存储，而不是 K 线索引，也不是屏幕像素。
- 同一批图形应出现在所有图表周期中。
- 在任意图表中编辑某个图形时，更新的是同一个全局图形，并同步到所有图表。
- 第一阶段的交互范围包括：
  - 选中
  - 可见控制点
  - 拖拽编辑
  - 拖拽移动
  - 矩形创建
  - 自动持久化

## 5. 架构

在 `ui/drawings/` 下引入一个专门的绘图子系统，包含以下职责划分。

### 5.1 GlobalDrawingStore

负责保存规范化后的绘图 spec，作为唯一事实源。

职责：

- 分配稳定的 drawing id
- 以 id 为键保存图形
- 增加、更新、删除、清空图形
- 暴露有序遍历能力，用于渲染顺序和命中优先级
- 对图形进行序列化和反序列化，以支持持久化

这个 store 是单一真相源。图表本地的 pyqtgraph item 只是派生视图，不得成为真实状态来源。

### 5.2 DrawingController

负责交互状态与修改流程编排。

职责：

- 跟踪当前选中的 drawing id
- 为创建工具启动 drawing session
- 判断一次鼠标按下是命中了控制点、图形主体还是空白区域
- 管理拖拽生命周期
- 将图形更新提交回 store
- 在创建、更新、删除或清空后触发持久化

controller 基于规范化 spec 工作，并把图表相关的显示职责委托给图表本地适配层。

### 5.3 EditableDrawingItem 基类契约

每一种可编辑图元类，都表示“某个图形在某个图表上的一个实例”，并实现统一接口。

必备能力：

- 应用规范化后的 drawing spec
- 渲染普通状态与选中状态
- 暴露可选中的控制点
- 判断某个屏幕位置是否命中控制点或图形主体
- 在拖拽期间更新内存中的预览 spec
- 从 plot 中移除该图形对应的所有 pyqtgraph item

通过这个统一接口，controller 和图表适配层就可以用同一种方式处理不同工具。

### 5.4 各工具专用的可编辑图元类

第一批专用图元类包括：

- `EditableHLineItem`
- `EditableVLineItem`
- `EditableLineItem`
- `EditableFibItem`
- `EditableFibExtensionItem`
- `EditableRectItem`

每个类负责：

- 主体图元创建
- 选中态样式
- 控制点图元创建与布局
- 各自工具特有的拖拽行为

### 5.5 ChartDrawingLayer

每个 `ChartWidget` 都有一个绘图图层适配器，用来把全局 store 连接到当前图表。

职责：

- 为当前图表中可显示的图形创建可编辑图元实例
- 维护本地图形映射 `drawing_id -> EditableDrawingItem`
- 当 store 中某条图形变化时，只更新或替换对应的本地图元
- 让本地图表的选中态与 controller 保持一致
- 将 plot 坐标转换为交互所需的 `时间 + 价格`

图表 widget 继续负责市场数据渲染、十字光标、回放、缩放和平移。

### 5.6 持久化

图形持久化与视图状态持久化分开处理。

职责：

- 将全局图形保存到 `QSettings`
- 在应用启动时恢复图形
- 容忍损坏的持久化数据，并在必要时回退为空图形集

`Save View` 继续只负责保存视图导航状态。图形持久化应当是自动的，不通过按钮触发。

## 6. UI 与交互设计

### 6.1 工具栏

保留现有绘图工具栏，并新增 `Rect`。

预期工具栏按钮为：

- `Sel`
- `H`
- `V`
- `Line`
- `Fib`
- `Fib Ext`
- `Rect`
- `Fib Config`
- `Clear`

`Sel` 成为显式的图形编辑模式。创建类工具仍然保留基于模式的工作方式。

### 6.2 选择模型

在 `Sel` 模式下：

- 左键点击图形即可选中
- 选中图形会显示高亮样式和控制点
- 左键点击空白处会取消选中
- 按下 `Delete` 删除当前选中的图形
- 右键菜单中的 `Delete Drawing` 继续作用于当前选中图形

当某个创建工具处于激活状态时，点击行为优先用于落点创建，不进入编辑模式。

### 6.3 拖拽生命周期

对可编辑图形而言：

1. 鼠标按下时判断目标是控制点、图形主体还是空白区域。
2. 鼠标移动时更新内存中的预览 spec，并原地刷新当前图形显示。
3. 鼠标释放时将更新后的 spec 提交到 `GlobalDrawingStore`。
4. store 更新后同步到所有图表，并触发持久化。

持久化只发生在提交时，不会在每一帧鼠标移动时写入。

### 6.4 各工具交互规则

#### HLine

- 图形主体就是这条水平线
- 拖拽主体时，修改保存的价格
- 因为它横跨整个图表，所以不需要处理水平方向移动

#### VLine

- 图形主体就是这条垂直线
- 拖拽主体时，修改保存的时间戳
- 因为它纵跨整个图表，所以不需要处理垂直方向移动

#### Line

- 选中后显示两个端点控制点
- 拖拽某个端点，只移动该端点
- 拖拽线段主体时，两个端点按相同的时间与价格偏移量整体平移

#### Fib

- 选中后显示两个锚点控制点
- 拖拽某个锚点时，更新该锚点，并重新计算所有回撤层级
- 拖拽主体时，两个锚点按相同的时间与价格偏移量整体平移
- 层级标签使用图形中保存的快照 levels，随锚点更新而刷新

#### Fib Ext

- 选中后显示三个锚点控制点
- 拖拽任意锚点时，重新计算扩展层级
- 拖拽主体时，三个锚点按相同的时间与价格偏移量整体平移
- 层级标签使用图形中保存的快照 levels，随锚点更新而刷新

#### Rect

- 创建方式是两个对角点
- 选中后显示四个角控制点
- 拖拽某个角时，以对角为固定参考，更新矩形边界
- 拖拽矩形主体时，整个矩形按相同的时间与价格偏移量整体平移

### 6.5 Clear 行为

`Clear` 清空的是全局 drawing store，而不是当前图表本地的图形。

所有图表都应立即移除全部图形，同时将空状态写入持久化存储。

## 7. 数据模型

继续使用规范化后的 drawing spec，并扩展以支持矩形与持久化。

线段示例：

```python
{
    "id": 8,
    "type": "line",
    "points": [
        {"dt": ..., "price": 3300.0},
        {"dt": ..., "price": 3320.0},
    ],
}
```

矩形示例：

```python
{
    "id": 17,
    "type": "rect",
    "points": [
        {"dt": ..., "price": 3301.25},
        {"dt": ..., "price": 3320.50},
    ],
}
```

Fibonacci 扩展示例：

```python
{
    "id": 22,
    "type": "fib_ext",
    "points": [
        {"dt": ..., "price": 3300.0},
        {"dt": ..., "price": 3330.0},
        {"dt": ..., "price": 3315.0},
    ],
    "config_snapshot": {
        "levels": [0.618, 1.0, 1.272, 1.618, 2.0],
    },
}
```

本轮支持持久化的图形类型包括：

- `hline`
- `vline`
- `line`
- `fib`
- `fib_ext`
- `rect`

## 8. 持久化格式

图形通过现有应用的 `QSettings` 实例持久化：

```python
QSettings("TradeReview", "TradeReview")
```

使用专门的 key，例如：

- `drawings/version`
- `drawings/items`

其中 `drawings/items` 保存为一个 JSON 数组，内容是规范化后的 drawing spec。

持久化 JSON 示例：

```json
[
  {
    "id": 17,
    "type": "rect",
    "points": [
      {"dt": "2026-04-17T09:30:00-04:00", "price": 3301.25},
      {"dt": "2026-04-17T11:00:00-04:00", "price": 3320.5}
    ]
  }
]
```

持久化规则：

- 时间戳以 ISO8601 字符串保存，若有时区则保留时区信息
- 价格保存为浮点数
- 新建图形后自动保存
- 拖拽编辑提交后自动保存
- 删除或清空图形后立即保存
- 选中状态不做持久化

错误处理规则：

- JSON 整体损坏时，回退为空图形列表
- 单条记录损坏时，仅跳过该记录，不中断整体恢复
- 未知图形类型直接忽略

## 9. 坐标映射

用户希望图形锚定在 `时间 + 价格` 上，而不是某个文件里的 K 线索引。这要求时间到 x 坐标的映射比当前“强制夹到边界”的逻辑更灵活。

要求：

- 如果图形时间戳落在当前数据范围内，就使用对应的 x 索引
- 如果图形时间戳早于当前可见数据的最早时间，就按图表时间步长向左外推
- 如果图形时间戳晚于当前可见数据的最晚时间，就按图表时间步长向右外推
- 不能悄悄把超出范围的图形塌缩到第一根或最后一根 K 线

这样即使当前加载的数据并不完全覆盖某个图形的时间范围，也能保留全局绘图库的语义。

## 10. 渲染与命中测试

### 10.1 渲染策略

当 store 变化时，每个图表只更新受影响的图形实例。

- add：创建一个新的可编辑图元
- update：替换或刷新对应图元
- delete：只移除对应图元
- clear：移除全部图元

避免每次更新都执行一次完整的 `clear_drawings()` 然后全量重建，否则会增加闪烁，也会让后续交互逻辑更难维护。

### 10.2 命中测试

命中优先级应为：

1. 控制点
2. 图形主体
3. 空白区域

命中容差应基于屏幕空间距离，而不是只看数据坐标距离，否则缩放级别变化后，选中手感会不稳定。

当多个图形重叠时，优先级为：

1. 最近一次被选中的图形
2. 否则是最近一次创建的图形

这样能得到一个稳定且可预测的选择规则。

### 10.3 选中样式

选中图形应通过以下方式与未选中图形区分：

- 更粗或更亮的主体线条
- 可见的控制点标记
- 持续保持选中，直到用户另选其他图形或点击空白处

未选中图形不显示控制点。

## 11. 测试策略

为新架构和新行为增加有针对性的测试覆盖。

### 11.1 Store 与持久化测试

新增测试覆盖：

- 增加、更新、删除、清空
- id 分配
- JSON 序列化与反序列化
- 持久化数据损坏时的恢复行为

### 11.2 Spec 与工具测试

扩展或新增测试覆盖：

- 矩形 spec 归一化
- 持久化时间戳解析
- 现有工具的 legacy spec 兼容性
- 矩形创建 session 的行为

### 11.3 可编辑图元测试

新增测试覆盖：

- 拖拽线段端点时是否正确更新锚点
- 拖拽线段主体时是否整体平移两个锚点
- 拖拽矩形角点时是否正确更新边界
- 拖拽 Fibonacci 锚点时是否重新计算派生层级
- 只有在选中时才显示控制点

### 11.4 图表集成测试

新增测试覆盖：

- `Sel` 模式下的选中
- 在一个图表中编辑后，是否同步到另一个图表
- 通过 chart widget 创建矩形
- 删除当前选中的图形
- `Clear` 是否清空所有图表中的图形

### 11.5 会话与启动测试

保留现有视图状态测试，并扩展验证：

- 启动时是否恢复图形
- 图形是否独立于当前数据库文件进行持久化
- 损坏的持久化绘图数据是否不会阻塞应用启动

## 12. 实现说明与风险

- 第一版仍应由 controller 主导事件分发。各 editable item 负责暴露命中测试和更新方法，但由 controller 决定当前处于何种交互状态。
- `Fib` 和 `Fib Ext` 的主体拖拽，第一版可以先实现为所有锚点的统一平移，不必一开始就加入更复杂的几何约束或吸附规则。
- 如果直接深度继承 pyqtgraph item 类带来不稳定行为，可以优先考虑“薄包装”或“组合”方式实现图元。
- 键盘删除功能要谨慎处理，只应在图形已选中且 chart widget 拥有焦点时生效。

## 13. 结果

完成后，系统应具备以下能力：

- 图形可以被选中并直接编辑
- 可以创建和编辑矩形
- 图形在应用重启后仍然保留
- 所有周期显示同一套全局图形
- 代码库拥有一套专门的绘图子系统，可继续支持通道、射线、文本标注等后续工具
